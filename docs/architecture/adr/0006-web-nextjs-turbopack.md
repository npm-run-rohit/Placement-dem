# ADR-0006: Web app on Next.js 16 with Turbopack (replaces Vite)

- Status: Accepted (29 Oct 2026, Rohit)
- Context: The web app was a Vite + React 18 SPA. The decision is to build it on Turbopack, which ships only inside Next.js. The app must stay hostable as static files under `/placement` in the BimaSahayak shell (ADR-0003), keep react-router routes and the static preview mode, and read `@bimaplacement/contracts` from source.
- Decision: Next.js 16 (App Router, Turbopack for `next dev` and `next build`), React 19. Next's documented Vite migration path: one optional catch-all page (`src/app/[[...slug]]/page.tsx`) renders the existing react-router app client-side (`dynamic(..., { ssr: false })` -> `src/Root.tsx`). Production builds use `output: 'export'` (static files in `apps/web/dist`, preview in `dist-demo`); `next dev` rewrites `/api` to the Nest API on :4000. Env vars move from `VITE_*` to `NEXT_PUBLIC_*`; `VITE_BASE` becomes `NEXT_PUBLIC_BASE_PATH` (no trailing slash). `turbopack.root` is the monorepo root so the contracts source path resolves.
- Consequences: No server rendering, server components or Next routing yet (the app is client-only, as before); screens can move to Next routes later one at a time. Deep links on the static host still need an index.html fallback. The preview build is a static folder, no longer a single self-contained HTML file. `vite preview` has no replacement script; serve `dist/` with any static server.
